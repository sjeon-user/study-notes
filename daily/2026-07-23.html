① ROS2 핵심 개념 — "회사(공장)" 비유

ROS2 시스템 전체를 여러 프로그램이 협력하는 회사로 보면 개념이 한 번에 잡힙니다.

🧑‍💼
Node = 직원일 하나만 맡는 담당자. 한 명이 죽어도 회사 전체는 안 멈춤.
📄
Message = 서류 양식정해진 데이터 포맷. 양식이 맞아야 대화가 통함.
📢
Topic = 게시판일방적 방송. 계속 흐르는 데이터(센서·영상).
☎️
Service = 전화 문의요청→응답 1:1. 가끔 필요할 때(명령·조회).
📦
Action = 택배 추적오래 걸리는 작업 + 중간 경과 + 취소 가능.
⚙️
Parameter = 설정판그 직원이 일하는 방식(설정값). 잘 안 바뀜.
개념비유핵심
Node직원일 하나만 맡는 담당자
Message서류 양식정해진 데이터 포맷
Topic게시판일방적 방송, 계속 흐르는 데이터 (센서)
Service전화 문의요청→응답 1:1, 가끔 필요할 때 (명령)
Action택배 추적오래 걸리는 작업 + 경과 보고 + 취소
Parameter개인 설정판그 직원이 일하는 방식(설정값)
Topic vs Service 한 줄 기준
계속 흘러나오는 것(영상·센서) → Topic (게시판에 계속 붙이기)
물어보고 답 받아야 하는 것(계산·명령) → Service (전화해서 확인)
Service vs Action — "밸브 열어"처럼 순식간에 끝나면 Service, "로봇암 이동"처럼 몇 초 걸리고 진행률/취소가 필요하면 Action.

② 실제 로봇 시스템 매핑

예: 카메라로 물체를 보고 → 로봇암으로 집어 → 솔레노이드 밸브(공압 그리퍼)로 작동하는 픽앤플레이스 스테이션.

📢 Topic — 계속 흐르는 데이터

발행 NodeTopicMessage구독자
센서/force_sensorWrench(힘/토크)로봇암1, 관제
카메라/camera/imageImage비전처리, 관제
로봇암1/arm1/joint_statesJointState관제

☎️ Service — 순간적으로 끝나는 명령

요청 → 담당Service내용
관제 → 밸브/valve/set"밸브 열어/닫아" → 즉시 응답 (그리퍼 잡기/놓기)
관제 → 카메라/camera/capture"지금 한 장 찍어줘" → 사진 1장
솔레노이드 밸브 = Service의 대표 사례. 열고/닫기가 순식간에 끝나고 답이 바로 옴 (센서처럼 계속 흐르지 않음 → Topic 아님).

📦 Action — 오래 걸림 + 경과 보고

요청 → 담당Action흐름
관제 → 로봇암1/arm1/move_to주문("좌표로 이동") → 경과("60%...") → 완료("도착"), 중간 취소 가능

⚙️ Parameter — 각 장비의 설정값

NodeParameter값(예)
카메라resolution / fps / exposure1920×1080 / 30 / auto
로봇암1max_velocity / max_accel0.3 m/s / 1.0
센서force_threshold5.0 N

🔄 한 사이클 흐름

1. 카메라 ──[Topic /camera/image]──▶ 관제       (물체 스트리밍)
2. 관제 ──[Service /camera/capture]──▶ 카메라   (정밀 1장 → 좌표 확보)
3. 관제 ──[Action /arm1/move_to]──▶ 로봇암1     ("물체 위로" 50%..100%)
4. 센서 ──[Topic /force_sensor]──▶ 관제         (그리퍼 닿는 힘 감지)
5. 관제 ──[Service /valve/set:OPEN]──▶ 밸브      (공압 그리퍼 잡기)
6. 관제 ──[Action /arm1/move_to]──▶ 로봇암1     (목표 위치로 이송)
7. 관제 ──[Service /valve/set:CLOSE]──▶ 밸브     (놓기 → 배치 완료)

④ I/O 제어기 (MOXA ioLogik E1212)

원격 이더넷 I/O 모듈. 로봇/자동화 시스템에서 컴퓨터와 현장 장치를 잇는 "원격 I/O 브리지" 역할을 하는 장비.

항목사양
제조사/모델MOXA ioLogik E1212
디지털 입력 (DI)8채널
디지털 출력 (DO)8채널
통신Modbus TCP (이더넷)
장착 / 보호DIN 레일, 절연(isolation) 내장

I/O 제어기의 기능 = "현실 ↔ 컴퓨터 통역기"

컴퓨터는 숫자(0/1)만, 현실 장치는 전기(24V 있음/없음)만 다룸. 이 둘을 잇는 다리.

🔵
DO 8ch (출력)컴퓨터 → 현실. 밸브 열기, 릴레이 작동, 트리거.
🟢
DI 8ch (입력)현실 → 컴퓨터. 스위치·근접센서·TOOL_ID·도어 감지.
🌐
이더넷/Modbus멀리서 원격 제어. LAN 한 줄로 확장, 절연으로 노이즈 차단.
검토 포인트
① E1212는 디지털(ON/OFF) 전용 — 아날로그(힘센서 전압 등)는 별도 모델(E1240/E1260 등) 필요.
② 채널 수(8/8) — 밸브·릴레이·TOOL_ID·도어 합산 후 수량/모델 결정.
③ 밸브·24V 릴레이 직접 구동 가능 여부(출력 전류) 확인, 부족하면 중간 릴레이.

⑤ PC ↔ I/O제어기 ↔ 장치 신호 흐름

구간마다 신호의 언어가 다름. I/O 제어기가 "통신 패킷 ↔ 전기신호"를 통역.

  • PC ↔ I/O제어기 : 이더넷 위 디지털 통신 (Modbus TCP 패킷)
  • I/O제어기 ↔ 장치 : 전기 접점 (24V 있음/없음)

🔵 출력 방향 (PC → 장치): "밸브 열어"

   PC (ROS2)              MOXA E1212              솔레노이드 밸브
 ┌──────────┐   Modbus   ┌──────────┐   전기접점   ┌──────────┐
 │ SetIO.srv│─── TCP ───▶│  DO 3번   │──── 24V ────▶│  밸브 ON  │
 │ "DO3 ON" │  (이더넷)   │  채널 ON  │  (전선 2가닥) │  (개방)   │
 └──────────┘            └──────────┘              └──────────┘
   ① 명령         ② 패킷        ③ 통역       ④ 전기(24V)     ⑤ 동작

🟢 입력 방향 (장치 → PC): "툴 체결됐나?"

   툴 체결 스위치           MOXA E1212               PC (ROS2)
 ┌──────────┐   전기접점   ┌──────────┐   Modbus   ┌──────────┐
 │  스위치   │──── 24V ───▶│  DI 1번   │─── TCP ───▶│ReadToolId │
 │  눌림     │  (전선)      │  = 1 감지 │  (이더넷)   │  = "체결"  │
 └──────────┘             └──────────┘             └──────────┘
중요 — 입력은 PC가 "주는" 게 아니라 "읽는" 것.
출력(DO): PC가 능동적으로 써넣기(Write) — "3번 켜"
입력(DI): PC가 주기적으로 물어보기(Polling) — "지금 입력값 뭐야?" (예: 20~50ms마다)

PC에서 실제로 어떻게? (Modbus 레지스터 읽기/쓰기)

하는 일Modbus 함수코드대상
입력 읽기 (DI)0x02 Read Discrete InputsDiscrete Input
출력 주기 (DO)0x05/0x0F Write Coil(s)Coil
from pymodbus.client import ModbusTcpClient
client = ModbusTcpClient("192.168.127.254")   # E1212 IP
client.connect()

# 입력(DI) 읽기: 채널 0부터 8개
di = client.read_discrete_inputs(address=0, count=8)
tool_attached = di.bits[1]          # DI 1번 = 툴 체결 스위치

# 출력(DO) 주기: 밸브가 DO 3번에 연결
client.write_coil(address=3, value=True)    # 밸브 열기 (24V ON)
client.write_coil(address=3, value=False)   # 밸브 닫기 (OFF)
실무 주의
① 0-기준 vs 1-기준 주소 — 라이브러리/장비마다 ±1 차이, 실제 채널은 테스트로 확인.
② 정확한 레지스터 번지는 MOXA E1212 데이터시트로 확인.
③ 안전 입력(E-STOP, TOOL_ID)은 폴링 지연 = 반응 지연 → E1212의 능동 통지 기능 검토.
한 줄 정리
PC ↔ I/O제어기 = LAN선 위 디지털 대화(Modbus TCP)
I/O제어기 ↔ 장치 = 전선 위 24V 전기(ON/OFF)
I/O 제어기 = 이 둘을 실시간 통역하는 중간 다리.
